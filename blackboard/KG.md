# Exposome flow map (knowledge graph)

How the merged blackboard drawing ([IMAGES.md](IMAGES.md)) was turned into a
digital knowledge graph, on 2026-11-11. Everything is in
[`exposome_map/`](exposome_map/).

## Idea

The orange writing on the board is read as a map of an exposome flow:

source → emission → chemical → transformation → exposure route → organ →
biological response → adverse outcome

Each step is a node in a network graph. Knowledge about adverse outcome
pathways (AOPs) is used as context for the biological part. Characteristics of
the individual, such as gender and age, affect the response. The purple
writing adds how things are measured: omics methods and exposome assessment.

## Files

| File | Role |
| :-- | :-- |
| `exposome_map.ttl` | The graph in RDF/Turtle. This is the source; edit this file. |
| `match_ontology.py` | Looks up the node labels on ExpoPortal and writes the mappings file. |
| `exposome_map_mappings.ttl` | Generated by `match_ontology.py`: the ontology terms found per node. Part of the graph. |
| `build_map.py` | Builds all files below from the two Turtle files. |
| `exposome_map.jsonld` | Generated: the same graph as JSON-LD. |
| `exposome_map.mmd` | Generated: Mermaid flowchart. |
| `exposome_map.svg` | Generated: clickable SVG in blackboard style, on a white background. |
| `exposome_map.png` | Generated: the SVG as an image, at twice its size. |
| `exposome_map.html` | Generated: the SVG in a web page. Hovering a node shows its ontology terms. |

```sh
python exposome_map/match_ontology.py   # only when labels changed; needs network, about 1 minute
python exposome_map/build_map.py
```

Both scripts need rdflib (Debian package `python3-rdflib`). The PNG needs
`rsvg-convert`; without it the script skips the PNG and says so.

## Content

59 nodes and 69 links, plus 96 ontology terms matched to 34 of the nodes
(1265 triples in total).

- **Two workflows.**
  - Biogenic: biogenic → α-pinene → inhalation → lung.
  - Anthropogenic: anthropogenic → tires → 6PPD → ozonolysis → 6PPD-Q →
    inhalation → lung, with tire-road wear emissions, TRWPs and
    micro-nanoplastics alongside.
- **Biological response.** One group, the big bracket on the board. It holds
  ROS pathway, NF-κB, catalase, signalling pathways, ERK-dependent and
  ERK-independent signalling, allergy, macrophages, eosinophils, inflammation,
  epithelial-mesenchymal transition, unjamming transition, fibrosis and asthma.
- **Modifiers.** Gender, age, smoking history and genes point at the
  biological response as a whole. "Male, 60 yrs" and "female, 20 yrs" are
  example groups linked to gender and age.
- **Omics methods.** Genome measures ROS pathway and NF-κB, proteomics
  measures catalase. Metabolomics, lipidomics and adductomics measure the
  biological response as a whole.
- **Exposome assessment.** External (individual and wearable silicone
  samplers, active and passive sampling) and internal (biomonitoring in blood,
  urine, milk, saliva and hair), both with targeted and non-targeted HRMS.

## How the graph is modelled

- **Identifiers.** Every node has a unique IRI with a readable local name,
  such as `em:chem_6ppd` or `em:ke_inflammation`. The namespace
  `https://example.org/exposome-map/` is a placeholder. To change it, change
  the `em:` prefix in the Turtle and the `EM` constant in `build_map.py`.
- **Node classes** are the stages of the flow: source, emission,
  chemical / stressor, chemical role, transformation process, exposure route,
  organ, receptor, process group, key event, adverse outcome, modifier, omics
  method, exposome assessment, sampling method, matrix and analytical method.
- **Each node** has a label, a short definition, alternative labels where
  useful, the ink colour and board it came from, and the workflow it belongs
  to.
- **Links** are plain triples with a small own vocabulary (`em:emits`,
  `em:exposureVia`, `em:leadsTo`, `em:measures`, `em:modifies`, and so on).
  `skos:broader` is used for "is a kind of".
- **Layout hints.** `em:x` and `em:y` give each node a place on a grid. The
  SVG is drawn from these, so a new node needs both values.

## Ontology terms from ExpoPortal

Added on 2026-11-11, following the approach of the earlier term-matching work
(`match_terms.py` in `background/expo/`).

- **Lookup.** `match_ontology.py` takes every label of a node (`rdfs:label`,
  `skos:altLabel` and `skos:hiddenLabel`) and compares it, ignoring case, with
  the labels and exact synonyms of all ontology terms on
  [ExpoPortal](https://expoportal.biohackeu.bigcat-bioinformatics.org). It
  queries the public SPARQL endpoint, the same backend as the ExpoPortal MCP
  server. The MCP tool itself returns at most 100 rows per query, which is too
  few for this lookup; it was used to cross-check a few results (α-pinene,
  age, antioxidant, blood).
- **Search variants.** `skos:hiddenLabel` holds spelling variants that are
  used only for the lookup, such as "macrophage" for "macrophages" or
  "signal transduction" for "signalling pathways".
- **In the graph.** A match is stored as `em:labelMatch` from the node to the
  ontology term. Each ontology term has its label and the ExpoPortal
  ontologies that contain it (`em:inOntology`). At most eight terms are kept
  per node, those found in most ontologies first.
- **Result.** 34 of 59 nodes have at least one match. Without a match are,
  among others, 6PPD, 6PPD-Q, TRWPs, micro-nanoplastics, ozonolysis,
  lipidomics, adductomics, unjamming transition, smoking history and the
  exposome assessment nodes.
- **In the page.** In `exposome_map.html` a node with a match has a dot.
  Hovering or focusing it opens a popup with the ontology terms: label, IRI
  and one link per ontology that opens the term on ExpoPortal. A click keeps
  the popup open. A node without a match has no popup.

The matches are automatic and not curated. Some are wrong: "AGE" in the
Protein Ontology for age, "EMT" in the mass spectrometry ontology for
epithelial-mesenchymal transition, and a fruit-fly "macrophage". `em:labelMatch`
only says that the labels are equal.

## Curator matches

Added on 2026-11-12.

- **Two kinds of match.** `em:labelMatch` is a match found by the script.
  `em:curatorMatch` ("manual curator match") is a match chosen by a person.
- **Rejecting a match.** `em:curatorNoMatch` ("manual curator no match") says
  that a term is wrong for a node. It overrules a label match of that node
  with that term: the page does not show it, and `make match` does not add it
  again. Other label matches of the node are not affected.
- **Evidence.** The kind of evidence comes from the Evidence and Conclusion
  Ontology (ECO), which is on ExpoPortal. ECO has classes only, no properties,
  so it cannot give a superproperty itself. The properties are therefore
  defined in the map vocabulary and point to their ECO class with
  `em:evidenceType`:
  - `em:automaticMatch`, the superproperty of `em:labelMatch`:
    ECO:0000501, "evidence used in automatic assertion".
  - `em:curatorMatch` and `em:curatorNoMatch`: ECO:0000305, "curator
    inference used in manual assertion".
- **Where to write them.** In `exposome_map_mappings.ttl`, above the line
  `# ==== generated by match_ontology.py: do not edit below this line ====`.
  Everything above that line is kept exactly as it is by `make match`:
  the matches, comments, extra prefixes and anything else written there.
  Everything below it is written again.
- **Safeguards.** `make match` stops without changing the file when a curator
  match or no match is below the marker line, when the marker line is missing from a file
  that has lines written by hand, or when the file is not valid Turtle.
- **Labels.** A term in a curator match gets its label and ontologies from
  ExpoPortal on the next `make match`. A label or ontology written by hand
  above the marker line replaces the one from ExpoPortal.
- **In the page.** The popup lists curator matches first, marked "chosen by a
  curator"; the others are marked "matched on label".

## Chemical structures

Added on 2026-11-12.

- **Which nodes.** A node with a ChEBI term as curator match or label match,
  for example 6PPD (CHEBI:747835).
- **SMILES.** `match_ontology.py` looks up the ChEBI identifier (P683) on
  [Wikidata](https://www.wikidata.org) and takes the isomeric SMILES (P2017)
  if there is one, else the canonical SMILES (P233). It is stored on the ChEBI
  term as `em:smiles`, with the Wikidata item as `rdfs:seeAlso`, at the end of
  `exposome_map_mappings.ttl`.
- **Updating.** `make match` looks up the structures too. `make structures`
  looks up only the structures and leaves the label matches as they are; it
  takes a few seconds. Neither runs in the GitHub Action.
- **By hand.** An `em:smiles` written above the marker line is used instead of
  the one from Wikidata, and is kept.
- **In the page.** The popup shows the 2D structure under the ChEBI term. The
  image is drawn by [CDK Depict](https://cdkdepict.toolforge.org/) from the
  SMILES. It is not stored in the page: the browser of the reader asks CDK
  Depict for it when the popup opens.
- **Result.** 5 of the 6 ChEBI terms have a structure: 6PPD, 6PPD-Q,
  α-pinene, ozone and hydroxyl. "antioxidant" (CHEBI:22586) is a role and has
  no structure.

## Choices to check

- **Links from AOP knowledge.** Seven links are not on the board: ROS pathway
  → NF-κB → inflammation, macrophages and eosinophils → inflammation,
  inflammation → epithelial-mesenchymal transition → fibrosis, and
  inflammation → asthma. They use their own predicate, `em:leadsToAOP`, and
  are dashed in the SVG, so they are easy to filter or remove.
- **Outcome or key event.** The board lists epithelial-mesenchymal transition
  and unjamming transition under "outcome". Here they are key events, and only
  fibrosis and asthma are adverse outcomes.
- **Heterogeneous oxidation** takes 6PPD and •OH as input but has no product,
  because the board names none.
- **Left out.** "Search & Findability", "Neurosymbolic AI", "AOP",
  "gaps / use cases", the DNA and protein sketch, and the pink note
  "GT / SESIV", which could not be read with confidence.

## The diagrams

- **SVG.** Orange is the flow, purple the annotations, as on the board. Lines
  and boxes have a hand-drawn wobble that is computed in the script, so no SVG
  filter is needed and the file renders quickly everywhere. Every node is a
  link with a tooltip that shows its definition.
- **Mermaid.** A plain flowchart, grouped by node class, with the same links
  and tooltips. It does not use the blackboard style.

## How it was checked

- The JSON-LD was read back and compared with the Turtle: same graph.
- The SVG is valid XML and renders with `rsvg-convert`.
- The script checks that node identifiers are unique and that every node has
  layout hints.
- The web page was loaded in headless Chromium: no script errors, a popup
  opens for a node with a match (macrophages) and none for a node without
  (6PPD).

Not checked: the Mermaid file was not rendered, because no Mermaid tool was
available. The popup was tested with simulated mouse events, not with a real
mouse, and the ExpoPortal links in it were not opened.

## Next steps

   the node identifier (for example `id="chem_6ppd"`), with a `data-iri`
   attribute and an outline of class `node-box` that can be filled or styled.
2. **Curate the ontology terms.** Pick the right term per node from the
   label matches and record it as `em:curatorMatch`. A node can also get a
   `skos:exactMatch`. The links in the SVG and
   the Mermaid diagram then point there instead of to the placeholder IRI.
